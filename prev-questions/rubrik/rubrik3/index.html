    Rubrik‑Themed DSA Pack (30 Problems) — Senior Software Engineer (India)¶

    Each problem is inspired by Rubrik’s domain (backup, snapshots, dedupe, restores, policy engines, distributed storage). For every item: problem ➜ constraints ➜ approach ➜ complexity ➜ key edge cases. Code snippets are Python‑ish pseudocode unless noted.

    1) Snapshot Interval Merge (Policy Compliance)¶

    Problem. Given N snapshots each with [start, end] retention windows, merge overlaps and return total retained time and the merged intervals.
    Constraints. 1 ≤ N ≤ 1e5; intervals within 64‑bit time; return sorted non‑overlapping intervals.
    Approach. Sort by start; sweep merging by extending the current end if overlapping; accumulate duration.
    Complexity. O(N log N) time, O(N) space.
    Edge cases. Touching intervals [a,b] & [b,c] should merge if policy says “inclusive end”; empty durations. 

    def merge_intervals(A):
    A.sort()
    out=[]; cur=None
    for s,e in A:
        if not cur or s>cur[1]:
            if cur: out.append(cur)
            cur=[s,e]
        else:
            cur[1]=max(cur[1],e)
    if cur: out.append(cur)
    total=sum(e-s for s,e in out)
    return out,total

    2) Incremental Backup Planner (Min Deltas)¶

    Problem. Given daily changed‑byte counts C[i] and a weekly full backup cost F, choose which days to take full vs incremental to minimize total cost over M days; incremental on day i costs C[i]. Full resets incremental accumulation.
    Approach. DP: dp[i]=min(F+dp[i+1], C[i]+dp[i+1]) but with a constraint “at least one full per 7 days”. Use DP with windowed constraint or monotone deque.
    Complexity. O(M) time, O(M) space (can optimize to O(1)).
    Edge cases. Start/end of week boundaries; zero‑change days.

    3) Multi‑Tenant Quota Enforcement (Sliding Window)¶

    Problem. For per‑tenant write requests (tenantId, t) enforce quota ≤ K requests in any sliding window of W seconds; return allow/deny stream.
    Approach. HashMap tenant→deque of timestamps; pop while t - deque[0] >= W; allow if len< K.
    Complexity. Amortized O(1)/request.
    Edge cases. Large tenant fan‑out; clock skew; exactly‑W boundary.

    4) Dedup Index: First Duplicate Chunk¶

    Problem. Stream of chunk hashes H[ ] (64‑bit). Find the first index that repeats a previously seen hash.
    Approach. HashSet; return earliest index that appears twice, or −1. For memory constraints, use Bloom + second‑pass verify.
    Complexity. O(N) time, O(N) space.
    Edge cases. Collisions if using 32‑bit; can mention double‑hashing.

    5) Restore Window Coverage (Minimum Tapes)¶

    Problem. You have tapes each covering a set of time intervals for a dataset. Choose minimum number of tapes whose union covers a requested window [L,R].
    Approach. Greedy interval covering: sort by start; extend farthest end while start ≤ current_end.
    Complexity. O(N log N).
    Edge cases. Gaps (impossible restore), multiple optimal choices.

    6) Immutable Log Compaction¶

    Problem. Given append‑only log segments with key,value,ts, compact to newest value per key while preserving order by ts for ties. Return compacted sequence.
    Approach. Process from newest to oldest tracking seenKeys; output when first time encountered; reverse at end.
    Complexity. O(N).
    Edge cases. Multiple updates same ts; tombstones.

    7) Snapshot Dependency Graph (Topological Restore)¶

    Problem. Snapshots form a DAG (incrementals depend on previous). Given a target snapshot node, return restore order.
    Approach. Reverse topological order from target: DFS to collect ancestors, then topologically sort subgraph or do post‑order and reverse.
    Complexity. O(V+E).
    Edge cases. Multiple parents (multi‑base); cycles invalid — detect.

    8) Consistent Hash Ring Rebalance¶

    Problem. Given N nodes on a consistent hash ring and M virtual nodes each, compute movement percentage of keys when adding one node.
    Approach. In a perfect hash, expected movement ≈ 1/(N+1); programmatically simulate: sort points, compute intervals absorbed by new node points.
    Complexity. O((N·M) log (N·M)).
    Edge cases. Non‑uniform vnode distribution.

    9) Throttle Restore Streams (Token Bucket)¶

    Problem. Implement per‑job token bucket: requests of size s must acquire s tokens; tokens refill at rate R/sec up to burst B.
    Approach. Track tokens and lastRefillTs; on request, refill then check tokens>=s.
    Complexity. O(1).
    Edge cases. Large bursts; float precision; time reversal.

    10) Tiering to Cold Storage (Knapsack Variant)¶

    Problem. Select files to move to cold storage so that freed hot‑tier size ≥ S while minimizing “future expected read cost” value. Each file i has size si and future read penalty pi.
    Approach. 0/1 knapsack by capacity S (minimize penalty while size≥S). Convert to maximize negative penalty; or DP by total size.
    Complexity. O(N·S) pseudo‑poly; for big S use greedy on ratio or meet‑in‑the‑middle.
    Edge cases. Exact S not possible, choose ≥ S minimal penalty.

    11) Windowed Change‑Rate Anomaly (Prefix/Suffix)¶

    Problem. Given bytesWritten[i], mark indices where 7‑day average deviates > T× from 28‑day baseline.
    Approach. Prefix sums for O(1) window averages; compare ratios.
    Complexity. O(N).
    Edge cases. Division by zero baseline; leading windows.

    12) File‑System Tree Compression (Run‑Length Path)¶

    Problem. Compress repetitive directory paths (e.g., a/a/a/a/b) into (segment, count) form; support decompress.
    Approach. Split by '/', run‑length encode contiguous equal segments.
    Complexity. O(L).
    Edge cases. Empty segments, root handling.

    13) Change‑Set Diff (Minimal Operations)¶

    Problem. Two ordered lists of chunk IDs A and B; compute minimal edits (insert/delete/retain) to transform A→B.
    Approach. Classic edit distance with backtracking, or LCS to derive edits (keep on LCS, delete otherwise, insert for extras in B).
    Complexity. O(nm) DP; for large use Hunt‑Szymanski or Myers O((n+m)D).
    Edge cases. Duplicates; memory.

    14) Backup Schedule Generator (Cron Simplifier)¶

    Problem. Given constraints: daily at HH:MM, weekly on D at HH:MM, skip holidays list — generate next K fire times.
    Approach. Iterate forward using min‑heap of rule candidates; skip if date in holidays.
    Complexity. O(K log R).
    Edge cases. DST transitions; leap years.

    15) Snapshot Space Forecast (Exponential Smoothing)¶

    Problem. Forecast next 30‑day storage usage from daily totals.
    Approach. Single exponential smoothing or moving average; implement ES with alpha.
    Complexity. O(N).
    Edge cases. Cold starts, abrupt jumps.

    16) Data‑Shard Repair (BFS on Erasure Groups)¶

    Problem. Erasure coding groups G with nodes; some nodes down. Find minimal set of remaining nodes to reconstruct a shard.
    Approach. For each group, if k of n available, choose any k (greedy). If cross‑group parity exists, model as bipartite selection and run BFS/DFS to find feasible picks.
    Complexity. O(E) for simple k‑of‑n; NP‑hard variants if cross‑deps complex.
    Edge cases. Multiple optimal; tie‑break by load.

    17) Point‑in‑Time Restore (Binary Search)¶

    Problem. Given sorted snapshot timestamps and a target time T, find snapshot ≤ T that minimizes T−snapshot.
    Approach. Binary search lower_bound.
    Complexity. O(log N).
    Edge cases. Before first; after last.

    18) Parallel Restore Planner (Top‑K Disjoint Files)¶

    Problem. For M files with sizes and conflict sets (can’t restore two conflicting simultaneously due to device contention), pick batches to maximize bytes/sec.
    Approach. Greedy with max‑heap on size filtering by conflicts; or reduce to maximum weighted independent set on interval/resource graph (heuristic).
    Complexity. Heuristic O(M log M).
    Edge cases. Many conflicts => small batches.

    19) Chunk Coalescing (Monotonic Stack)¶

    Problem. Given chunk sizes along a stream, coalesce adjacent chunks if combined size ≤ L, maximizing number of merges. Return final partition.
    Approach. Stack of segments; try to merge top with incoming while total ≤ L.
    Complexity. O(N).
    Edge cases. Large single chunk; exact equality.

    20) Policy Engine — First Match Wins¶

    Problem. Rules R[i] with predicates on (tenant, path, tag). For requests, return the first matching rule’s action. Rules can be added dynamically.
    Approach. Build trie on path + hash on tenant + bitsets for tags; evaluation orders: tenant → path → tag. Maintain rule order per bucket.
    Complexity. O(L + log B).
    Edge cases. Shadowed rules; rule deletion.

    21) Audit Log Sampling (Reservoir)¶

    Problem. Stream of audit events; keep a uniform sample of size K over unbounded stream.
    Approach. Reservoir sampling (Vitter’s algorithm).
    Complexity. O(N) time, O(K) space.
    Edge cases. K≥N → keep all.

    22) Version Graph Garbage Collection¶

    Problem. Directed acyclic version graph; given a set of pinned versions, delete minimal number of unpinned nodes that are not on any path from a root to a pinned node. Return deletable nodes.
    Approach. Mark phase: reverse‑reachability from pinned; sweep: delete unmarked.
    Complexity. O(V+E).
    Edge cases. Multiple roots; large fan‑out.

    23) Distributed Lease Renewal (Heartbeats)¶

    Problem. Track N jobs sending heartbeats; detect expirations after T seconds of silence and return expired job IDs periodically.
    Approach. Min‑heap keyed by nextExpiry; map job→heapIndex; on heartbeat, update expiry and heapify.
    Complexity. O(log N) per heartbeat.
    Edge cases. Duplicate heartbeats; clock skew; spurious time jumps.

    24) Restore Consistency Checker (Union‑Find)¶

    Problem. N files with constraints “file a must be restored before b” and “a conflicts with b (cannot co‑exist)”. Determine if constraints are satisfiable.
    Approach. Toposort for order constraints; conflict constraints → 2‑SAT/Union‑Find on components with parity if expressing mutual exclusion; or detect if any cycle or co‑location contradiction.
    Complexity. O(V+E).
    Edge cases. Self‑conflict; duplicate constraints.

    25) Hotset Cache — LFU with Aging¶

    Problem. Implement LFU cache with periodic aging (halve counts every T). Supports get/put.
    Approach. Standard LFU (freq→DLL buckets), plus background “aging” to avoid stale heavy hitters.
    Complexity. O(1) amortized per op.
    Edge cases. Ties by recency; size 0.

    26) Cloud Snapshot Pricing (Binary Search on Answer)¶

    Problem. Given per‑GB price tiers and a budget B, find maximum data X that can be stored without exceeding B.
    Approach. Binary search X; cost(X) via prefix of tiers.
    Complexity. O(log Range).
    Edge cases. Non‑contiguous tiers; off‑by‑one at boundaries.

    27) Immutable Map with Snapshots (Persistent DS)¶

    Problem. Implement a versioned map supporting put(key,val) returning new version ID, and get(key, versionId).
    Approach. Persistent balanced BST or Hash‑array‑mapped trie (HAMT) with structural sharing.
    Complexity. O(log N) per op.
    Edge cases. Memory blowup without sharing; tombstones.

    28) Tape Robot Scheduler (Intervals + Heap)¶

    Problem. Given tape mount requests (start, duration) and one robot arm, schedule to minimize late mounts.
    Approach. Sort by start; use min‑heap by finish; simulate; or use EDF with preemption if allowed.
    Complexity. O(N log N).
    Edge cases. Overlapping long jobs; preemption policy.

    29) Multi‑Region Restore Latency (Min‑Cut Insight)¶

    Problem. Regions graph with bandwidth capacities. For requested data size S from region A to B, find minimal completion time if flows can use multiple paths.
    Approach. Max‑flow on capacity graph; time ≈ S / maxflow. Return maxflow and suggested path split.
    Complexity. O(E·sqrt(V)) or Dinic O(EV).
    Edge cases. Disconnected; per‑edge latency not considered (note extension to min‑cost flow).

    30) Alert Flood Deduplication (Time Buckets)¶

    Problem. Collapse identical alerts arriving within Δ seconds into one with count. Return collapsed stream.
    Approach. HashMap key→(lastTs,count); if ts - lastTs ≤ Δ, increment count; else emit new.
    Complexity. O(N).
    Edge cases. Out‑of‑order alerts; window stitch across boundaries.

    Appendix: Quick Patterns & Why They Fit Rubrik¶

    • Intervals & sweeps for retention & restore windows.
    • Graphs/Topo/Flow for snapshot DAGs, dependency orders, and multi‑region bandwidth.
    • Heaps & deques for schedulers, sliding windows.
    • Union‑Find/2‑SAT for constraint satisfiability.
    • Persistent DS models immutable snapshots.
    • Binary search on answer for cost/latency caps.
    • Streaming (reservoir, token bucket) for audit/throttle.
